# 学生网页编码一日监控与回收方案

用途：学生编码预计需要一天，本方案用于当天督促、状态核验和数据回收。它不记录访问口令，不进入公开论文附件。

## 一、当天目标

- 主编码任务：120 条。
- 双编码复核任务：24 条。
- 学生人数：10 人。
- 每名学生工作量：12 条主编码，加 2-3 条复核编码。
- 当前线上状态：已提交 6 条主编码，0 条复核编码。

当天完成标准不是“学生都登录过”，而是线上数据库达到：

| 指标 | 目标 |
|---|---:|
| 主编码提交 | 120 |
| 复核编码提交 | 24 |
| 完整提交行 | 144 |
| 复核覆盖视频 | 24 |

## 二、给学生的简短说明

可以直接转发以下说明，但访问口令请另发：

> 请打开网页编码系统，使用分配给你的学生编号登录。每条任务必须先点“打开视频”，观看视频画面、字幕、标签、动作节奏和平台语境后再填写。不要只凭标题填写，也不要照抄系统提示。缺视频链接的任务按页面提示暂缓，不需要硬填。备注只写匿名观察，不写用户名、主页、手机号、评论者身份或原始链接。

## 三、建议时间点

| 时间点 | 教师动作 | 判断 |
|---|---|---|
| 第 0 小时 | 发送网页、学生编号、访问口令和填报说明 | 确认 10 名学生都收到 |
| 第 2 小时 | 看线上提交数是否增长 | 若某学生 0 提交，单独提醒 |
| 第 6 小时 | 检查主编码是否超过 60 条 | 低于 60 条则延长截止或补充提醒 |
| 第 12 小时 | 检查主编码和复核编码 | 主编码应接近 120，复核应开始出现 |
| 第 24 小时 | 导出并运行完整审计 | 决定是否需要返工 |

## 四、回收后的处理

学生完成后运行：

```bash
python3 scripts/run_qigong_post_web_coding_pipeline.py
```

该流水线依次完成：

1. 导出 Supabase 网页提交。
2. 转换为正式人工编码表。
3. 审计字段完整性和取值合法性。
4. 生成正式结果表。
5. 计算双编码一致性。
6. 生成分歧复核表。
7. 刷新投稿门槛。

## 五、进入论文结果写作的门槛

只有同时满足以下条件，才能把网页人工编码写成正式结果：

- 主编码完整提交达到 120 条。
- 双编码复核达到 24 条。
- `web_reliability_gate.md` 无 fail。
- `audit_qigong_coding_values.py --profile formal` 无关键 fail。
- 分歧复核表中核心变量没有未处理的系统性分歧。

未达到上述条件时，论文只能写“网页人工编码平台已建立，学生编码正在进行”，不能写“编码结果显示”。
