# Benchmark-to-Claim Matrix

This matrix keeps benchmark choice tied to the paper's claims. Co-Pilot AI
Scientist v3 should not be evaluated by defaulting to whichever benchmark is
easiest to run. Each benchmark is included only if it measures a specific part
of the system claim.

## Selection Rule

Future runs should be selected by the weakest unsupported claim, not by
convenience. The next highest-value run is a single online trajectory with
idea, evaluator, branch, program-search, and claim gates active in one
continuous experiment, followed by a matched autonomous baseline under the same
budget. After that, the benchmark suite should scale the now-scored official
repair the full official BabyLM eval path and run a larger BabyLM budget, add
another official task whose data path is already accessible, or scale the
matched end-to-end trajectory suite, rather than treating two narrow scored
official-evaluator paths plus one tiny compatibility score as broad official
coverage.

Because the current paper is cost-constrained, future benchmark expansion
should be staged. Small version-chain and deep-regeneration pilots should first
identify which review signals, gate routes, and frontier metrics are promising;
only those designs should be expanded into large historical replay or
prospective human-review studies.
